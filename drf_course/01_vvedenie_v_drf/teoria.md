# Урок 1. Введение в DRF и REST API

## Что такое API?

**API (Application Programming Interface)** — «программный интерфейс».
Проще говоря — способ, которым две программы общаются друг с другом.

Представь себе ресторан. Ты (клиент) не заходишь на кухню и не готовишь
еду сам. Ты смотришь в **меню** (это и есть интерфейс), делаешь заказ
официанту, и он приносит готовое блюдо. Кухня — это сервер, меню — это
API, официант — HTTP-запрос.

В вебе API обычно работает так:
- клиент (браузер, мобильное приложение, другой сервер) отправляет запрос
  по определённому адресу (URL);
- сервер обрабатывает запрос и возвращает ответ (обычно в формате JSON).

## Что такое REST?

**REST (Representational State Transfer)** — это набор правил (архитектурный
стиль) для построения API. RESTful API опирается на несколько принципов:

1. **Всё — это ресурс**. Пост, комментарий, пользователь — у каждого свой URL:
   - `/api/posts/` — список постов
   - `/api/posts/5/` — пост с id=5

2. **Действия задаются HTTP-методами**, а не названиями в URL:
   - `GET /api/posts/` — получить список
   - `POST /api/posts/` — создать новый
   - `PUT /api/posts/5/` — полностью обновить
   - `PATCH /api/posts/5/` — частично обновить
   - `DELETE /api/posts/5/` — удалить

3. **Статус ответа — в HTTP-коде**:
   - `200 OK` — всё хорошо
   - `201 Created` — создано
   - `400 Bad Request` — ошибка в запросе
   - `404 Not Found` — не найдено
   - `500 Internal Server Error` — ошибка сервера

4. **Ответ в формате JSON** (обычно). JSON — текстовый формат,
   понятный и людям, и машинам:
   ```json
   {
       "id": 1,
       "title": "Мой первый пост",
       "body": "Текст поста..."
   }
   ```

## Django и REST: что даёт DRF?

Обычный Django (как в твоём блоге) отдаёт HTML-страницы. Это удобно для
пользователей-людей, но неудобно для других программ (мобильное приложение,
React-фронтенд, другой сервер).

**Django REST Framework (DRF)** — это библиотека (надстройка над Django),
которая добавляет в проект возможность легко создавать REST API.

Без DRF ты бы писал всё вручную: превращал модели в JSON, разбирал входящие
данные, проверял HTTP-методы, формировал ответы... DRF берёт эту скучную
работу на себя.

### Что даёт DRF:

- **Сериализаторы** — автоматически превращают модели Django в JSON и обратно
- **Готовые views** — обработчики для типичных действий (CRUD)
- **ViewSets и Routers** — автоматическая генерация URL для API
- **Browsable API** — веб-интерфейс для тестирования API прямо в браузере
- **Аутентификация** — токены, сессии, OAuth из коробки
- **Permissions** — настройка прав доступа к API

## Установка DRF

DRF устанавливается как обычная Python-библиотека:

```
> pip install djangorestframework
```

После установки нужно зарегистрировать DRF в настройках Django. Открой
файл `config/settings.py` и добавь `rest_framework` в список `INSTALLED_APPS`:

```python
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'blog',
    'rest_framework',   # ← добавь эту строку
]
```

После этого DRF готов к работе. Никаких дополнительных миграций не нужно —
DRF технически не хранит своих данных, он только добавляет новые views,
сериализаторы и инструменты поверх существующего Django.

## Твой проект и API: что мы будем делать

У тебя есть проект-блог с моделями `Post` и `Comment`. В ходе курса мы
превратим его в полноценное API:

- можно будет получать список постов через `GET /api/posts/`;
- создавать посты через `POST /api/posts/`;
- редактировать, удалять;
- работать с комментариями;
- добавим аутентификацию (только автор может править свой пост);
- добавим документацию через Swagger.

При этом **старый сайт (HTML-страницы) останется работать** — API будет
дополнением, а не заменой.

## Зачем нужен API, если уже есть сайт?

- **Мобильное приложение** — сайт есть, но телефону нужны «чистые» данные
- **Фронтенд на React/Vue** — SPA (Single Page Application) запрашивает
  только данные и рендерит их сам
- **Интеграция** — другой сервис может читать/создавать посты через API
- **Микросервисы** — разделение проекта на независимые части

## Словарик терминов

- **API** — интерфейс для общения программ между собой
- **REST** — архитектурный стиль: ресурсы, HTTP-методы, статус-коды
- **JSON** — текстовый формат обмена данными (ключ: значение)
- **Endpoint** — конкретный URL, по которому доступен ресурс
- **CRUD** — Create, Read, Update, Delete — четыре базовые операции
- **DRF** — Django REST Framework, библиотека для построения API
