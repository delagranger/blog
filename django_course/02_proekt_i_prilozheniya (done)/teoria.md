# Урок 2. Проект и приложения

## Проект vs приложение: в чём разница?

В Django есть два важных понятия, которые новички часто путают.

- **Проект (project)** — это весь твой сайт целиком. Обычно у тебя один
  проект. В нём хранятся общие настройки всего сайта.
- **Приложение (app)** — это отдельный «кубик» внутри проекта, который
  решает одну задачу. Например: блог, форум, магазин, чат.

Проект собирается из нескольких приложений, как конструктор.

```
Мой проект (сайт)
├── Приложение «Блог»      ← посты и комментарии
├── Приложение «Пользователи» ← регистрация и вход
└── Приложение «Магазин»   ← товары и корзина
```

Почему так удобно? Приложение можно перенести из одного проекта в другой.
Например, ты написал приложение «форум» — и можешь вставить его в любой
свой будущий сайт, как готовую деталь.

## Создаём проект

Убедись, что виртуальное окружение активировано (в начале строки должно
быть `(venv)`), и выполни:

```
> django-admin startproject config .
```

Разберём по частям:

- `django-admin` — программа для управления Django.
- `startproject` — команда «создать проект».
- `config` — имя папки с настройками проекта. Мы используем общепринятое
  имя `config`, чтобы не путать его с приложениями.
- `.` (точка) — «создай проект прямо в текущей папке». Без точки Django
  создал бы лишнюю вложенную папку.

После выполнения появится примерно такая структура:

```
config/
└── settings.py      ← настройки всего проекта
└── urls.py          ← главная таблица адресов сайта
└── wsgi.py, asgi.py ← технические файлы запуска
manage.py            ← главный помощник разработчика
```

## Что такое manage.py?

`manage.py` — это твой главный инструмент. Через него ты будешь:

- запускать сервер разработки;
- создавать приложения;
- применять миграции;
- открывать интерактивную консоль.

Самая частая команда записывается так:

```
> python manage.py runserver
```

## Запускаем сервер разработки

Выполни команду из шага выше и увидишь примерно такое:

```
Starting development server at http://127.0.0.1:8000/
```

Открой браузер и перейди по адресу http://127.0.0.1:8000/ — увидишь
приветственную страницу Django с ракетой. Это значит, что проект работает!

- **127.0.0.1** — специальный адрес «этого компьютера» (его ещё называют
  localhost).
- **:8000** — порт, «дверь», через которую браузер общается с сервером.

Чтобы остановить сервер, вернись в терминал и нажми `Ctrl + C`.

## Ключевой файл: settings.py

`config/settings.py` — это пульт управления проектом. Сейчас бегло посмотри
на самые важные настройки (их смысл раскроется в следующих уроках):

- `INSTALLED_APPS` — список установленных приложений. Чтобы Django узнал
  о приложении, его нужно добавить сюда.
- `DATABASES` — настройки базы данных.
- `LANGUAGE_CODE` и `TIME_ZONE` — язык и часовой пояс сайта.
- `SECRET_KEY` — секретный ключ безопасности (никогда не публикуй его).

## Создаём приложение

Создадим приложение для блога:

```
> python manage.py startapp blog
```

Появится папка `blog/` с файлами:

- `models.py` — модели (данные), урок 4.
- `views.py` — представления (логика), урок 3.
- `admin.py` — настройка админ-панели, урок 5.
- `apps.py` — настройки самого приложения.
- `migrations/` — папка для миграций (изменений базы данных), урок 4.

## Подключаем приложение к проекту

Приложение создано, но проект о нём ещё не знает. Открой `config/settings.py`,
найди `INSTALLED_APPS` и добавь туда `"blog"`:

```python
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    # ... другие встроенные приложения ...
    "blog",          # ← наше приложение
]
```

Теперь Django «видит» наш блог.

## Словарик терминов

- **Сервер разработки** — программа, которая запускает твой сайт у тебя
  на компьютере, чтобы ты мог проверять его в браузере. Для настоящего
  интернета в конце используют другой, «боевой» сервер.
- **Порт** — числовой адрес-«дверь», через которую идёт общение.
- **Модуль** — в Python это просто файл с кодом (например, `views.py`).
