# Урок 1. Введение и установка

## Что такое веб-фреймворк?

Представь, что ты хочешь построить дом. Ты можешь делать кирпичи сам,
мешать цемент вручную и с нуля придумывать каждую мелочь. А можешь взять
готовый каркас, где уже есть окна, двери и проводка — и просто расставить
мебель.

**Веб-фреймворк** — это и есть такой «готовый каркас» для сайтов. Он берёт
на себя скучную и повторяющуюся работу:

- общение с базой данных (хранилищем информации);
- обработку адресов страниц (URL);
- защиту паролей и вход пользователей;
- работу с формами и многое другое.

Тебе остаётся написать только уникальную часть твоего сайта.

**Django** — один из самых популярных веб-фреймворков на языке Python.
Он создан по принципу «батарейки включены» (batteries included): из коробки
есть куча готовых инструментов — админ-панель, работа с пользователями,
формы, защита от взлома.

## Что такое MVT?

Django устроен по схеме **MVT** — Model, View, Template. Разберём каждую букву.

- **Model (Модель)** — описывает данные. Например, «пост в блоге» — это
  модель с полями «заголовок» и «текст». Модель хранит и достаёт данные
  из базы данных.
- **View (Представление)** — это «мозг». Оно получает запрос от посетителя,
  берёт нужные данные из моделей и решает, что показать.
- **Template (Шаблон)** — это «витрина». Файл с HTML-разметкой, куда View
  подставляет данные. Пользователь видит именно результат шаблона.

Как идёт запрос, когда ты открываешь страницу:

```
Ты вводишь адрес
      ↓
Django смотрит «какой View отвечает за этот адрес?»
      ↓
View берёт данные из Model
      ↓
View передаёт данные в Template
      ↓
Ты видишь готовую HTML-страницу
```

Если тебе раньше встречалась схема **MVC** — это почти то же самое.
В Django «Controller» по сути встроен в сам фреймворк, поэтому говорят MVT.

## Что такое «виртуальное окружение» (venv)?

Когда ты ставишь Python-библиотеки (пакеты), они ставятся глобально —
на весь компьютер. Проблема: разные проекты могут требовать **разные версии**
одной библиотеки. Один проект работает с Django 4, другой — с Django 5.
Ставить обе версии глобально нельзя.

**Виртуальное окружение** — это отдельная «комнатка» для каждого проекта.
Внутри неё свои версии библиотек, которые не мешают другим проектам.

Проще говоря: venv — это личная песочница для твоего проекта.

## Установка Python и Django

### Шаг 1. Проверь, установлен ли Python

Открой терминал (командную строку) и введи:

```
> python --version
```

Если Python установлен, ты увидишь что-то вроде `Python 3.12.2`.
Если нет — скачай и установи Python с официального сайта
https://www.python.org/downloads/ (при установке на Windows поставь галочку
«Add Python to PATH»).

### Шаг 2. Создай виртуальное окружение

Сначала перейди в папку проекта (замени путь на свой):

```
> cd путь_к_папке_проекта
```

Затем создай окружение командой:

```
> python -m venv venv
```

Появится папка `venv` — это и есть твоё виртуальное окружение.

### Шаг 3. Активируй окружение

Активация — это «вход» в песочницу. Пока окружение активно, все команды
`python` и `pip` работают внутри него.

- **Windows (командная строка):**

```
> venv\Scripts\activate
```

- **Windows (PowerShell):**

```
> .\venv\Scripts\Activate.ps1
```

- **macOS / Linux:**

```
> source venv/bin/activate
```

Если всё получилось, в начале строки появится `(venv)` — значит, ты внутри.

### Шаг 4. Установи Django

```
> pip install django
```

`pip` — это «установщик» библиотек для Python. Эта команда скачивает Django
из интернета и кладёт его в твоё окружение.

Проверь, что Django установился:

```
> python -m django --version
```

Ты увидишь номер версии, например `5.0.6`.

## Полезные команды на будущее

- `deactivate` — выйти из виртуального окружения.
- `pip list` — посмотреть список установленных библиотек.
