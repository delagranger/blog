ц# Урок 3. URL и Views

## Как Django понимает, какую страницу показать?

Когда ты вводишь в браузере адрес, например `http://127.0.0.1:8000/o-nas/`,
происходит следующее:

1. Django получает запрос и смотрит на «хвост» адреса — `/o-nas/`.
2. Находит в таблице адресов (URLconf) запись, которая совпадает с этим хвостом.
3. Передаёт запрос нужному **View** (представлению).
4. View возвращает ответ (HTML-страницу), которую браузер отображает.

Таблица адресов — это файлы `urls.py`. Их в проекте две:

- `config/urls.py` — главная таблица: куда направлять запросы.
- `blog/urls.py` — таблица конкретного приложения (создадим сами).

## Что такое View (представление)?

**View** — это просто функция (или класс) на Python, которая получает запрос
и возвращает ответ.

Минимальная функция-представление выглядит так:

```python
from django.http import HttpResponse


def glavnaya(request):
    return HttpResponse("Привет, это мой блог!")
```

Разберём:

- `request` — объект, в котором лежит вся информация о запросе посетителя:
  адрес, метод (GET или POST), данные формы. Django передаёт его
  автоматически.
- `HttpResponse` — готовый ответ, который Django отправит в браузер.
  Здесь это просто текст, дальше будем возвращать настоящий HTML.

## Связываем адрес и View: urls.py

Одного View мало — нужно сказать Django, по какому адресу оно открывается.
Для этого заглянем в `config/urls.py`. Там уже есть список `urlpatterns`:

```python
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),
]
```

- `path()` — связывает адрес с представлением.
- `"admin/"` — хвост адреса, при заходе на который откроется админка.

## Добавляем свою первую страницу

### Шаг 1. Напишем View

В файле `blog/views.py` напишем:

```python
from django.http import HttpResponse


def glavnaya(request):
    return HttpResponse("Привет, это мой блог!")
```

### Шаг 2. Создадим таблицу адресов приложения

В папке `blog/` создай файл `urls.py` (Django его сам не создаёт). Запиши:

```python
from django.urls import path
from . import views  # точка = текущая папка, т.е. blog

urlpatterns = [
    path("", views.glavnaya),  # "" — это корень сайта
]
```

Здесь `""` (пустая строка) означает адрес `/`. То есть при заходе на главную
страницу сработает `glavnaya`.

### Шаг 3. Подключим таблицу приложения к главной

Открой `config/urls.py` и добавь запись с функцией `include()`:

```python
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path("admin/", admin.site.urls),
    path("", include("blog.urls")),  # ← всё, что начинается с "/", отдаём блогу
]
```

- `include()` — «вставь сюда таблицу адресов из приложения blog».
  Так у каждого приложения свои адреса, и главный файл не разрастается.

Теперь запусти сервер (`python manage.py runserver`) и открой
http://127.0.0.1:8000/ — увидишь «Привет, это мой блог!».

## Адреса с параметрами

Часто адрес содержит какую-то переменную часть, например номер поста:

```
http://127.0.0.1:8000/post/3/
```

Здесь `3` — номер поста, и он каждый раз разный. В Django это делается так:

```python
# blog/urls.py
urlpatterns = [
    path("", views.glavnaya),
    path("post/<int:nomer>/", views.post_po_nomeru),
]
```

- `<int:nomer>` — «поймай из адреса целое число и положи его в переменную
  `nomer`».

Теперь View должен принять эту переменную:

```python
def post_po_nomeru(request, nomer):
    return HttpResponse(f"Ты открыл пост номер {nomer}")
```

Типы параметров в адресе:

- `<int:...>` — целое число (самое частое).
- `<str:...>` — любая строка без слэшей.
- `<slug:...>` — «красивый» фрагмент текста из букв, цифр и дефисов
  (используют для понятных ссылок).

## Методы GET и POST

Когда браузер общается с сервером, он использует «методы», то есть способы
запроса. Два главных:

- **GET** — «покажи мне страницу». Обычный переход по ссылке.
- **POST** — «прими мои данные». Отправка формы (например, логин или
  комментарий).

Внутри View можно узнать метод запроса:

```python
def glavnaya(request):
    if request.method == "GET":
        return HttpResponse("Это GET-запрос — просто показываем страницу")
    return HttpResponse("Это другой запрос")
```

Полностью с POST-запросами разберёмся в уроке про формы (урок 7).

## Словарик терминов

- **HTTP** — протокол, по которому браузер общается с сервером.
- **URLconf** — файл(ы) `urls.py`, таблица адресов сайта.
- **Маршрут / route** — пара «адрес + представление» в этой таблице.
- **HttpResponse** — ответ сервера браузеру.
