# Урок 7. Forms (формы)

## Зачем нужны формы?

Форма — это способ пользователя отправить данные на сервер: оставить
комментарий, зарегистрироваться, заполнить анкету. В HTML форма выглядит
как набор полей и кнопка «Отправить».

Django помогает работать с формами безопасно и удобно: он может
показывать форму, проверять введённые данные и сообщать об ошибках.

## Два вида форм в Django

1. **Простая форма (forms.Form)** — не связана с моделью. Сам описываешь
   поля, что нужно получить от пользователя (например, форма поиска).
2. **Форма модели (forms.ModelForm)** — создаётся на основе модели.
   Django сам подставляет поля из модели. Идеально для форм, которые
   добавляют или изменяют записи.

## Создаём форму модели

Пусть у нас есть модель `Comment` (комментарий к посту):

```python
from django.db import models


class Comment(models.Model):
    post = models.ForeignKey(Post, on_delete=models.CASCADE)
    imya = models.CharField(max_length=100)
    tekst = models.TextField()
```

Создай файл `blog/forms.py`:

```python
from django import forms
from .models import Comment


class CommentForm(forms.ModelForm):
    class Meta:
        model = Comment
        fields = ["imya", "tekst"]
```

Разберём:

- `forms.ModelForm` — «форма, построенная по модели».
- Внутренний класс `Meta` — настройки формы.
- `model = Comment` — на основе какой модели.
- `fields = ["imya", "tekst"]` — какие поля включить в форму.

## Показываем форму на странице

Создадим View. Обрати внимание на ветвление GET/POST — это ключевой момент:

```python
from django.shortcuts import render, redirect
from .forms import CommentForm


def dobavit_kommentariy(request):
    if request.method == "POST":
        form = CommentForm(request.POST)   # заполнили данными из запроса
        if form.is_valid():                # данные корректны?
            form.save()                    # сохраняем в базу
            return redirect("glavnaya")    # перенаправляем на главную
    else:
        form = CommentForm()               # пустая форма (GET)

    return render(request, "blog/forma.html", {"form": form})
```

Что здесь происходит:

- Пользователь просто открыл страницу (GET) → показываем пустую форму.
- Пользователь нажал «Отправить» (POST) → заполняем форму его данными,
  проверяем, сохраняем и перенаправляем.

## Шаблон формы

В Django форму в шаблоне можно вывести автоматически:

```html
<form method="post">
    {% csrf_token %}
    {{ form.as_p }}
    <button type="submit">Отправить</button>
</form>
```

- `method="post"` — данные уйдут POST-запросом.
- `{% csrf_token %}` — скрытый «жетон безопасности», защита от подделки
  запросов. Без него Django не примет POST-запрос.
- `{{ form.as_p }}` — вывести все поля формы, каждое в отдельном абзаце.

## Что такое CSRF

**CSRF** (Cross-Site Request Forgery) — вид атаки, когда злоумышленник
заставляет твой браузер отправить запрос от твоего имени. Django защищается
с помощью специального токена — уникального значения, которое вставляется
в форму и проверяется при отправке. `{% csrf_token %}` добавляет именно его.

## Проверка данных: is_valid()

Метод `is_valid()` проверяет введённые данные по правилам модели:

- все ли обязательные поля заполнены;
- правильный ли формат (например, e-mail);
- не превышена ли длина строки.

Если данные некорректны, `is_valid()` вернёт `False`, а форма «запомнит»
ошибки — их можно показать пользователю:

```html
{{ form.imya.errors }}
```

## Простая форма (forms.Form)

Иногда форма не связана с моделью. Например, форма поиска:

```python
from django import forms


class SearchForm(forms.Form):
    zapros = forms.CharField(label="Что ищем?", max_length=100)
```

Здесь мы вручную описываем поле `zapros`. В шаблоне она выводится так же,
через `{{ form.as_p }}`.

## Итоговая схема работы с формой

1. Пользователь открывает страницу → GET → пустая форма.
2. Пользователь заполняет и отправляет → POST.
3. View создаёт форму с данными `request.POST`.
4. `is_valid()` проверяет данные.
5. Если всё хорошо — сохраняем и перенаправляем.
6. Если ошибки — снова показываем форму с сообщениями об ошибках.

## Словарик терминов

- **GET/POST** — способы отправки запроса (показать / передать данные).
- **CSRF-токен** — защитный жетон против подделки запросов.
- **Валидация** — проверка корректности введённых данных.
